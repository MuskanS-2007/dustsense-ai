## 1. Executive Summary & Problem Statement

Fugitive dust ($PM_{10}$ and $PM_{2.5}$) generated by heavy construction earthworks, unpaved vehicular haulage, aggregate stockpiles, and material transfer chutes presents severe occupational and community respiratory hazards. Conventional monitoring installations are passive and lagging: they merely flag air quality exceedances after particulates have already crossed property boundaries.

**DustSentinel** is an intelligent, explainable decision-support dashboard designed for site environmental officers and equipment foremen. It integrates sensor data ingestion, aerodynamic dispersion modeling, deterministic multi-criteria source attribution, actionable mitigation playbooks, and simulated before-and-after intervention forecasting.

### Key Non-Goals & Integrity Boundaries
1. **No Opaque / Fictional ML Claims:** Source attribution uses an explainable, deterministic engineering rule engine based on particulate ratios, aerodynamics, and site activity. The system does not claim an opaque black-box machine learning model exists where one has not been trained and evaluated.
2. **No Uncalibrated Probabilities:** Rule-based scores are clearly designated as heuristic ranking scores or indices, not calibrated Bayesian probabilities.
3. **No Direct Physical Actuation:** The platform generates operational dispatch work orders and simulations; it does not directly control physical water pumps, valves, or vehicles.
4. **No Fictionalized Real-Time Claims:** Static or synthetic data is clearly labelled as simulated or synthetic, distinguishing it from live telemetry streams.

## 2. Core Operational Zones

The system monitors four designated construction zones:

| Zone Identifier | Spatial Sector | Characteristic Particulate Dynamics | Emission Trigger Mechanisms |
| :--- | :--- | :--- | :--- |
| **Excavation** | NW Sector ($X: 25, Y: 75$) | Coarse dust dominance ($PM_{10} \gg PM_{2.5}$), $PM_{2.5}/PM_{10} \approx 0.18\text{–}0.28$ | Bulk earthmoving, topsoil stripping, bulldozer cut/fill |
| **Haul Road** | Central Corridor ($X: 45, Y: 48$) | High episodic transients, high coefficient of variation ($CV > 0.35$) | Dump truck tire shear, silt resuspension on unpaved roads |
| **Material Storage** | NE Sector ($X: 78, Y: 78$) | Non-linear wind erosion lift ($U_{wind} > 18\text{ km/h}$, $RH < 40\%$) | Aerodynamic surface shear on exposed aggregate stockpiles |
| **Loading Point** | SE Sector ($X: 72, Y: 28$) | Cyclical plumes during material transfer batches | Hopper discharge, conveyor drops, high free-fall heights |

## 3. Functional Requirements & Acceptance Criteria

### REQ-01: Synthetic Data Generation & Scenario Reproducibility
- **Description:** Provide synthetic sensor streams generating $PM_{2.5}$, $PM_{10}$, wind speed, wind direction, ambient temperature, relative humidity, and activity level across diurnal cycles.
- **Scenarios Supported:**
  1. *Active Peak Shift (High Dust Event)*
  2. *Dry Windy Alert Condition*
  3. *Standard Operations*
- **Acceptance Criteria:**
  - Synthetic data generation must be deterministic given a seed, producing reproducible timestamps anchored to a normalized baseline (e.g. top of the hour) without floating-microsecond jitter.
  - UI must display a clear, permanent badge: `[SYNTHETIC TEST STREAM]`.

### REQ-02: CSV Schema Validation & Upload Bounds
- **Description:** Ingest custom sensor time-series via CSV with strict schema verification and file-size safety.
- **Schema:**
  - Required columns: `timestamp`, `zone`, `pm2_5`, `pm10`, `wind_speed`, `wind_deg`, `humidity`, `temperature`.
  - Optional column: `activity_level` (defaults to `Moderate` if omitted).
- **Acceptance Criteria:**
  - Maximum upload size capped at $15\text{ MB}$ to prevent memory exhaustion.
  - Reject or warn if $> 10\%$ of numeric rows cannot be parsed into valid floating-point numbers.
  - Produce an audit report showing row counts, timestamp ranges, and detected data issues.

### REQ-03: Data Quality, Integrity & Anomaly Management
- **Description:** Enforce rigorous data-quality controls without fabricating physical observations.
- **Acceptance Criteria:**
  - **REQ-03A (Zone-Scoped Imputation):** Missing-value interpolation or forward-filling must be strictly isolated **within each individual zone**. Sensor values must never cross zone boundaries. Gaps exceeding 30 minutes must not be forward-filled; they must remain marked as missing.
  - **REQ-03B (Duplicate Handling):** Records with duplicate `(timestamp, zone)` keys must be flagged. If values conflict, log the anomaly and apply a deterministic resolution (e.g. average or keep latest) with an explicit audit note.
  - **REQ-03C (Physical Bounds):** Negative particulate readings, negative wind speeds, or humidity $> 100\%$ must be flagged as `DATA_QUALITY_FAULT` rather than silently clamped into plausible values.
  - **REQ-03D (PM Consistency):** If $PM_{2.5} > PM_{10}$, the row must be flagged as `ANOMALY_PM_INVERSION` (indicating optical sensor drift or chamber contamination). The value must **NOT** be silently overwritten with an artificial multiplier.

### REQ-04: Risk Metrics & Regulatory Standard Distinction
- **Description:** Compute site risk tiers while maintaining strict technical accuracy regarding regulatory standards.
- **Thresholds:**
  - Instantaneous Action Alert: $PM_{10} \ge 100\ \mu\text{g/m}^3$ (Site Action Trigger)
  - Instantaneous Severe Hazard: $PM_{10} \ge 150\ \mu\text{g/m}^3$
  - WHO 24h Guideline: $45\ \mu\text{g/m}^3$ ($PM_{10}$), $15\ \mu\text{g/m}^3$ ($PM_{2.5}$)
  - US EPA NAAQS 24h Limit: $150\ \mu\text{g/m}^3$ ($PM_{10}$), $35\ \mu\text{g/m}^3$ ($PM_{2.5}$)
- **Acceptance Criteria:**
  - A single 15-minute point reading exceeding $150\ \mu\text{g/m}^3$ must be labelled as an **"Instantaneous Threshold Exceedance"**, NOT a statutory 24-hour EPA violation.
  - Compute a rolling 24-hour mean for true statutory compliance assessments when sufficient time-series data exists.

### REQ-05: Explainable Source Attribution & Aerodynamic Ranking
- **Description:** Rank the four site zones by likelihood of being the primary source of fugitive dust plumes.
- **Attribution Logic:**
  - Multi-criteria deterministic evaluation incorporating:
    1. Absolute particulate concentration ($PM_{10}$).
    2. Size fraction fingerprinting ($PM_{2.5}/PM_{10}$ ratio in $0.15\text{–}0.35$ indicates mechanical crustal dust; $> 0.45$ indicates combustion exhaust).
    3. Aerodynamic wind vector alignment (plume heading $(wind\_deg + 180^\circ) \bmod 360^\circ$ relative to sensitive receptor bearing).
    4. Physical triggers: wind speed $> 18\text{ km/h}$ and humidity $< 40\%$ for stockpile erosion; high variance for haul road.
    5. Operational machinery activity logs.
- **Acceptance Criteria:**
  - Output ranked zones ($1\text{–}4$) with transparent heuristic scores (labelled "Attribution Ranking Score", not "Confidence %").
  - Provide human-readable bulleted evidence explaining exactly which physical rules fired.

### REQ-06: Targeted Mitigation Playbook & Work-Order Dispatch
- **Description:** Supply actionable industrial engineering countermeasures tailored to each zone.
- **Catalog Requirements:**
  - Measures must include operational mechanism, time-to-deploy, expected particulate reduction efficacy range, and cost tier.
  - Cover water misting, speed limits, geotextile windbreaks, atomized mist cannons, and transfer chute enclosures.
- **Acceptance Criteria:**
  - Allow generating and downloading a structured operational work order (`.txt`) for site crews with assigned equipment, target zone, and re-verification timeline.
  - Maintain a session log of issued work orders.

### REQ-07: Simulated Before-and-After Intervention Sandbox
- **Description:** Provide an interactive sandbox allowing users to model the theoretical impact of deploying one or more mitigations.
- **Mathematical Formulations:**
  - Multi-intervention combined efficiency: $E_{combined} = 1 - \prod (1 - E_i \times \text{compliance})$.
  - Ambient background floor: baseline particulate cannot be reduced below regional background ambient air ($\sim 18\ \mu\text{g/m}^3\ PM_{10}$, $8\ \mu\text{g/m}^3\ PM_{2.5}$).
  - Operational time window: active mechanical controls only apply during working shift hours.
- **Acceptance Criteria:**
  - **Exceedance Clock Time Accounting:** Avoided exceedance hours must be computed across **unique elapsed timestamps**, NOT by summing simultaneous zone occurrences.
  - Label all metrics as **"Simulated Projections"**; document that transfer efficiencies are derived from empirical literature (e.g. US EPA AP-42 & WRAP Fugitive Dust Handbook) and do not represent verified causal measurements for the specific site.

### REQ-08: Separation of Simulation from Physical Observation
- **Description:** Ensure zero ambiguity between physical/measured sensor observations and algorithmically simulated projections.
- **Acceptance Criteria:**
  - All simulated cards, charts, and metrics must include explicit prefixes (e.g., "Simulated Projected Reduction", "Simulated Post-Mitigation PM10").
  - Prominent disclaimer banner maintained on the simulation tab.

### REQ-09: Event Logging & Data Export
- **Description:** Allow exporting both active sensor observations and simulated comparison datasets.
- **Acceptance Criteria:**
  - Provide one-click CSV export for cleaned active sensor records.
  - Provide one-click CSV export for the simulated post-mitigation dataset (`df_sim`) including projected $PM_{10}$ and $PM_{2.5}$ columns.

### REQ-10: Error Handling & System Reproducibility
- **Description:** Robust error recovery and pinned environment specifications.
- **Acceptance Criteria:**
  - Clean error recovery for empty datasets, single-row uploads, or invalid columns.
  - Supply reproducible dependency specifications compatible with Python 3.10+.

### REQ-11: Modular Testable Architecture & Automated QA
- **Description:** Decouple domain logic from Streamlit UI rendering to allow automated regression testing.
- **Acceptance Criteria:**
  - Core validation, ranking, and simulation functions isolated in `core_engine.py`.
  - Comprehensive automated unit tests implemented in `tests/test_engine.py` covering validation edge cases, cross-zone isolation, duplicate detection, and exceedance hour calculations.
  - All tests executable via standard test runners (`pytest` or Python `unittest`).
